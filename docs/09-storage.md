# เก็บรูปอย่างไรไม่ให้เปลืองพื้นที่

## สิ่งที่ระบบทำอยู่

| ขั้น | ค่า |
|---|---|
| ไฟล์ต้นทาง | รับได้ ≤ 10 MB |
| ประมวลผล | ด้านยาวสุด **1,600 px** (OCR/QR) |
| รูปที่จัดเก็บ | ด้านยาวสุด **1,280 px** |
| บีบอัด | **WebP q≈0.82** ถ้าเบราว์เซอร์ไม่รองรับ → JPEG q≈0.85 |
| เป้าหมาย | ≤ **600 KB/รูป** (ถ้าเกินจะลดคุณภาพ/ย่อเพิ่มอัตโนมัติ) |
| ไฟล์ที่บันทึก | ≤ **2 MB** (ตรวจซ้ำฝั่ง server/Apps Script) |
| จำนวนรูป | **1 รูปต่อ 1 คูปอง** ไม่มี thumbnail แยก |

ผลลัพธ์โดยประมาณ: 100 คูปอง ≈ **10–25 MB** (ขึ้นกับเนื้อหา screenshot)

## ทำไมไม่เปลือง

- ไม่เก็บ Base64 ใน Sheets — เก็บเฉพาะ `imageFileId`/`imageUrl`
- ไม่สร้าง thumbnail ซ้ำ — ใช้รูปเดียวกันทั้งการ์ดและหน้ารายละเอียด
- โหมดง่ายเก็บรูปเป็น Blob ใน IndexedDB; Base64 ใช้เฉพาะไฟล์สำรอง
- บีบอัดก่อนอัปโหลด → ประหยัดทั้ง Drive และ bandwidth
- ไม่บันทึกรูปจนกว่าจะกด “บันทึกคูปอง” → ไม่มีไฟล์ขยะจากการทดลอง
- ถ้ารูปซ้ำ ระบบเตือนก่อนบันทึก

## สิ่งที่ยังกินพื้นที่

- **Soft delete ยังเก็บรูปไว้** (ตามกฎเก็บหลักฐาน) — ถ้าต้องการคืนพื้นที่ต้องลบไฟล์ใน Drive/`.data` เอง
- รูปถูกเก็บตลอดอายุคูปอง + 1 ปี (ยังไม่มี auto-delete)
- Drive/Sheets มี quota ตามบัญชี Google

## ถ้าอยากประหยัดกว่านี้

1. ลด `MAX_EDGE` ใน `lib/image.ts` (เช่น 1200) — รายละเอียดอาจเล็กลง
2. ลด `TARGET_BYTES` (เช่น 400 KB) — ระบบจะบีบอัดเพิ่ม
3. ลบรูปของคูปองที่ใช้แล้ว/หมดอายุ ผ่าน Drive หรือเขียน cleanup script
4. ใช้ Google Drive แบบ shared drive ขององค์กรเพื่อบริหาร quota

> รูปมีไว้เป็นหลักฐานอ้างอิง — QR/รหัส/วันหมดอายุถูกเก็บเป็นข้อความแยกแล้ว จึงไม่ต้องเก็บรูปความละเอียดสูง
