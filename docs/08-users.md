# หลายผู้ใช้ (userId)

ข้อมูลคูปองแยกตาม **id ที่ผู้ใช้ตั้งเอง** ไม่มีระบบสมัคร/ล็อกอิน และทุก id เห็นเฉพาะข้อมูลของตัวเอง

## เส้นทาง

| หน้า | ทำอะไร |
|---|---|
| `/` | หน้าหลัก: สร้าง QR/บาร์โค้ด (ไม่บันทึก) |
| `/user` | พิมพ์ id เพื่อเข้ากระเป๋า |
| `/user/{id}` | กระเป๋าของ id นั้น |
| `/user/{id}/new` | เพิ่มคูปองให้ id นั้น |
| `/user/{id}/coupons/{couponId}` | รายละเอียด / edit / qr / history |

## กติกา id

- ตั้งเองได้: `a-z`, `0-9`, `-`, `_`
- ยาว 2–30 ตัว, normalize เป็นตัวพิมพ์เล็ก (`Tar` → `tar`)
- ตัวอย่าง: `/user/tar`, `/user/demo`

## การแยกข้อมูล

- ทุกคูปองมี `userId`
- การอ่าน/แก้/ใช้/ลบ/ดู history ต้องเป็นเจ้าของ id นั้นเท่านั้น
- ถ้าไม่ใช่เจ้าของ → `NOT_FOUND` (ไม่บอกว่ามีอยู่)
- ตรวจซ้ำ (duplicate) เฉพาะคูปองของ user เดียวกัน
- ไม่มี id พิเศษที่เห็นข้อมูลคนอื่น

## แชร์คูปองโดยไม่ต้องใช้ user

- ลิงก์: `/share/{couponId}`
- เปิดดูได้แบบอ่านอย่างเดียว (รูป/ชื่อ/QR/รหัส) โดยไม่ต้องมี userId
- มีปุ่มแชร์ในหน้ารายละเอียดและหน้า QR
- ใครมีลิงก์ก็เปิดได้; ถ้าคูปองถูกลบ ลิงก์จะเป็น 404
- couponId เป็นลำดับรายวัน (เช่น `CPN-261031-001`) จึงอาจเดาได้ — แชร์เฉพาะคนที่ต้องการ

## ความปลอดภัย (สำคัญ)

ยังไม่มี auth จริง:

- ใครรู้ id ก็เปิด `/user/{id}` และเห็นคูปองของ id นั้นได้
- id ที่เดาง่าย (เช่น `tar`, `demo`) ไม่ปลอดภัย
- ก่อนเปิด public ต้องเพิ่ม Google Login/PIN และผูก session กับ userId

## ที่เก็บ

| โหมด | ที่เก็บ userId |
|---|---|
| demo `.data` | ฟิลด์ `userId` ใน `db.json` |
| Google Sheets | คอลัมน์ `userId` (X) ท้ายชีต `Coupons` |

ข้อมูลรุ่นก่อนที่ยังไม่มี `userId`:

- demo → ย้ายเข้ากลุ่ม `legacy`
- Sheets → คอลัมน์ว่าง; อ่านเป็น id `legacy` (เปิดได้ที่ `/user/legacy`)

## ตัวอย่าง

```
/user/tar
/user/demo
```

API ต้องส่ง `userId` เสมอ:

```
GET  /api/coupons?userId=tar
POST /api/coupons            body: { userId, title, ... }
GET  /api/coupons/{id}?userId=tar
POST /api/coupons/{id}/use?userId=tar
```
